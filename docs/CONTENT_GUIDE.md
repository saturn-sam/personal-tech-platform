# PTKP Content Guide

Version: 1.0

Status: Approved

---

# Purpose

This document defines how all content within the Personal Technical Knowledge Platform (PTKP) is organized, created, maintained, and interconnected.

The objective is to ensure that every piece of content follows a consistent structure, writing style, metadata model, and relationship model.

This document is the authoritative guide for all future content.

---

# Content Philosophy

PTKP is a technical knowledge platform.

It is **not**:

- A personal portfolio
- A commercial website
- A product landing page
- A résumé website
- A documentation dump

Every page must teach something.

Every page should solve a problem.

Every page should contribute to a long-term knowledge base.

---

# Content Types

PTKP contains the following content collections.

## Articles

Technical articles explaining concepts, implementation approaches, operational guidance, and lessons learned.

---

## Lab Notes

Experimental work.

Lab Notes document:

- Tests
- Validation
- Failures
- Troubleshooting
- Benchmarks

Lab Notes may later become Articles.

---

## Architecture Guides

Long-form implementation guidance.

Examples:

- VMware Cloud Foundation
- Kubernetes Platform Design
- OpenShift Architecture
- NSX Design
- Disaster Recovery

---

## Projects

Real engineering implementations.

Each Project should document:

- Objective
- Architecture
- Design
- Implementation
- Challenges
- Lessons Learned

---

## Technologies

Reference documentation.

Examples:

- Kubernetes
- VMware
- OpenShift
- Terraform
- Ansible
- GitLab
- Django
- Oracle

---

## Certifications

Professional certifications.

Focus on:

- Skills validated
- Related technologies
- Practical application

Avoid treating certifications as awards.

---

## Resources

Curated learning references.

Include:

- Books
- Documentation
- Videos
- Courses
- RFCs
- Whitepapers
- Blogs

Only include resources you recommend.

---

## Learning Paths

Structured learning journeys.

Example:

Beginner Kubernetes

↓

CKA Preparation

↓

CKS Preparation

↓

Production Kubernetes

---

# Metadata

Every content type should contain metadata appropriate to its purpose.

Typical metadata includes:

- Title
- Description
- Publish Date
- Last Updated
- Tags
- Category
- Author
- Featured
- Draft
- Related Technologies
- Related Projects

---

# Internal Linking

Whenever appropriate, link content to:

- Technologies
- Projects
- Articles
- Architecture Guides
- Certifications
- Resources
- Learning Paths

Avoid isolated pages.

PTKP should behave as a connected knowledge graph.

---

# Naming

Use:

- Short titles
- Clear filenames
- Consistent slugs

Avoid abbreviations unless they are industry standards.

---

# Images

Images should:

- Support understanding
- Be optimized
- Have descriptive alt text

Avoid decorative images.

---

# Diagrams

Prefer:

- Mermaid
- Architecture diagrams
- Flow diagrams
- Sequence diagrams

Keep diagrams simple.

---

# Code

Code should:

- Compile where applicable
- Use syntax highlighting
- Be production quality

Avoid pseudo-code unless explaining concepts.

---

# Tables

Use tables when comparing:

- Technologies
- Features
- Versions
- Architectures

Avoid unnecessarily wide tables.

---

# Future Growth

Every new content type should integrate with:

- Existing metadata
- Existing relationships
- Existing layouts

Avoid introducing isolated content structures.

---

# Review Checklist

Before publishing content verify:

- Accurate
- Complete
- Technically correct
- Proper metadata
- Related links added
- Accessible
- Grammar checked
- Markdown validated

Only publish content that satisfies this checklist.
