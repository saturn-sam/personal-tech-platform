Version: 1.0

Status: Approved

# Purpose

Define the standard authoring process for every content type in PTKP.

This guide ensures consistency, technical quality, readability, and long-term maintainability.

# Writing Principles

- Write for engineers.
- Be technically accurate.
- Explain why before how.
- Prefer practical implementation.
- Include diagrams where useful.
- Include examples.
- Include references.
- Keep content evergreen.

---

# Article Structure

Every article should contain:

1. Title
2. Summary
3. Problem Statement
4. Background
5. Solution
6. Implementation
7. Validation
8. Best Practices
9. Troubleshooting
10. References
11. Related Content

---

# Project Structure

Every project should contain:

1. Overview
2. Business Objective
3. Technical Objective
4. Architecture
5. Design Decisions
6. Implementation
7. Challenges
8. Lessons Learned
9. References

---

# Technology Structure

Every technology page should contain:

1. Overview
2. Concepts
3. Installation
4. Configuration
5. Best Practices
6. Common Problems
7. References

---

1. Objective
2. Environment

# Architecture Guide Structure

1. Introduction
2. Requirements
3. Architecture

---

# Markdown Rules

- Use one H1.
- Maintain heading hierarchy.
- Use fenced code blocks.
- Specify language for every code block.
- Use tables for comparisons.
- Use Mermaid for architecture diagrams.

---

# Images

- Use descriptive filenames.
- Always provide alt text.
- Compress images before publishing.

---

# Internal Linking

Every document should link to:

- Related Technologies
- Related Projects
- Related Articles
- Related Resources

---

# Review Checklist

Before publishing verify:

- Technical accuracy
- Grammar
- Metadata
- Internal links
- References
- Accessibility
- Markdown formatting
- Build success
