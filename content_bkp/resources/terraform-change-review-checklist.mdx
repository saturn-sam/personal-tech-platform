## Why It Matters

Terraform changes can affect shared infrastructure quickly. A review checklist helps teams separate expected drift correction, module behavior, provider changes, and environment-specific risk before approval.

## How to Use This Resource

Apply this checklist during merge request review and before promotion to shared environments. Record unresolved questions before the apply stage begins.

```bash
terraform fmt -check
terraform validate
terraform plan -out=tfplan
```

## Review Areas

- Confirm provider and module version changes are intentional.
- Confirm remote state, locking, and workspace selection.
- Review create, update, replace, and destroy actions separately.
- Verify that pipeline approvals match the target environment risk.

## Related Practice

Use this resource with GitLab CI/CD project records. The checklist is most useful when plan evidence, approval context, and deployment history stay attached to the pipeline.
