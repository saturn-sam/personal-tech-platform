## Why It Matters

Node incidents are easier to handle when operators follow a consistent path. This checklist keeps the first pass focused on scheduler-visible state, pressure signals, recent events, and host service health.

## How to Use This Resource

Start with cluster-level visibility before logging into the host. If multiple nodes show the same condition, treat it as a platform or shared infrastructure signal before draining individual nodes.

```bash
kubectl get nodes -o wide
kubectl describe node worker-01
kubectl get events -A --sort-by=.lastTimestamp
```

## Checklist

| Area         | Question                                     | Evidence                    |
| ------------ | -------------------------------------------- | --------------------------- |
| Readiness    | Is the node schedulable and reporting Ready? | Node condition output       |
| Pressure     | Is memory, disk, or PID pressure present?    | Node description and events |
| Host service | Is kubelet healthy on the host?              | System service status       |
