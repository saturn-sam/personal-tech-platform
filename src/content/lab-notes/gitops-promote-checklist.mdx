Use this note before promoting a GitOps change into a shared environment. The goal is to make the review repeatable and reduce the chance that a promotion moves forward without the expected validation.

## Pre-Promotion Review

- Confirm the target environment and branch mapping.
- Review the manifest diff for unexpected resource changes.
- Validate required approvals and release ownership.
- Check whether the change affects observability, storage, or ingress behavior.

Read the [GitOps Promotion Checklist](/lab-notes/gitops-promotion-checklist/).

- Platform work
  - Kubernetes
  - GitOps

1. Review
2. Approve
   - Security check
   - Rollback check
3. Promote

```bash
git diff origin/main...HEAD
kubectl diff -f manifests/
```

## Drift Check

If the cluster differs from the repository state, investigate the cause before continuing. Drift can hide a deployment that is technically applied but not governed by the expected source of truth.

## Release Note

Record the promotion decision, the validation evidence, and the owner responsible for the change. This makes follow-up support simpler when the deployment causes an issue later.
